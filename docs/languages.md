# Languages

Every language Duck knows comes from the catalogue built into the binary:
its file types, tree-sitter grammar, comment tokens, indentation and
language servers. `~/.config/duck/languages.yaml` and a project
`.duck/languages.yaml` change or extend it, both are merged over the
catalogue in that order.

## Language servers

A language starts every server it lists that is installed, the editor
does not install servers. Features are combined: diagnostics of all
servers are shown together, other requests go to the first server that
offers them. `:lsp-restart` restarts the servers of the buffer, the log
(`:log-open`) says why one did not start, `DUCK_LSP_LOG=file` records every
message.

## Changing a language

Entries of your `languages.yaml` merge with the catalogue field by field,
so an override only needs what changes. To start from the catalogue entry:

```sh
dk export language go             # the go entry and its servers, on stdout
dk export queries go/highlights.scm   # one query file into ~/.config/duck/runtime/queries
dk export queries go              # all query files of a language
```

An exported query file replaces the built in one, also after updating dk.
`dk grammar check` lists the files that do, export only those you change.

## languages.yaml

The file has three sections, all optional. Unknown keys are errors with the
line they are on.

```yaml
# Servers shared by several languages or overridden by name.
language-servers:
  gopls:
    command: gopls
    config:
      hints:
        parameterNames: true
  ruff:
    command: ruff
    args: [server]

languages:
  # Change one field of a catalogue language, the rest stays.
  python:
    language-servers: [ruff, pyright]
    auto-format: true
  go:
    indent: { tab-width: 4, unit: "\t" }
    rulers: [100]
```

### Language keys

| Key                                                     | Meaning                                                                                                                          |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `file-types`                                            | extensions such as `go`, or `{ glob: Dockerfile.* }`                                                                             |
| `shebangs`                                              | interpreters that identify a file without a known extension                                                                      |
| `roots`                                                 | files marking the project root for language servers, such as `go.mod`                                                            |
| `glob-roots`                                            | `true` makes the globs match only next to one of `roots`                                                                         |
| `language-servers`                                      | server names in priority order, or `{ name, only-features, except-features }`                                                    |
| `formatter`                                             | `{ command, args }`, fed the text on stdin, formats instead of the language servers when installed                               |
| `check`                                                 | `{ command, args }` run right after a save when installed, `{file}` is the path. When it fails the old file goes back, see below |
| `auto-format`                                           | format on save                                                                                                                   |
| `code-actions-on-save`                                  | code action kinds run before saving, such as `source.organizeImports`                                                            |
| `indent`                                                | `{ tab-width, unit }`                                                                                                            |
| `comment-token` `comment-tokens` `block-comment-tokens` | for `C-c` and comment continuation                                                                                               |
| `auto-pairs`                                            | `false`, or a map of open to close characters                                                                                    |
| `soft-wrap` `rulers` `text-width`                       | override the editor options for the language                                                                                     |
| `language-id`                                           | identifier sent to servers when it differs from the name                                                                         |
| `grammar`                                               | the tree-sitter grammar, see below                                                                                               |
| `scope` `injection-regex`                               | scope name and the names that embed it in other languages                                                                        |

A glob without a slash matches the file name, one with a slash the end of
the path by whole directories, or the whole path when it starts with `/`.
`**` stands for any number of directories. When several globs match, the most
specific one wins. With `glob-roots: true` the globs of a language count only
when one of its `roots` lies in the directory the glob starts from: Helm has
`templates/**/*.yaml` with `roots: [Chart.yaml]`, so only the templates of a
chart are Helm and other `templates/` directories stay YAML.

An extension or glob belongs to one language only, a file type claimed twice
is an error. `:set-language` (`:lang`) changes the language of a buffer.

### Server keys

| Key                   | Meaning                                                                                                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `command` `args`      | the server program                                                                                                           |
| `environment`         | extra environment variables                                                                                                  |
| `config`              | settings sent as initialization options and on configuration requests                                                        |
| `except-code-actions` | code action kinds left out of the `space a` menu, a kind also hides those below it (`source` hides `source.organizeImports`) |

The catalogue hides `gopls.doc.features`, a link to the gopls documentation
offered with every request. Kinds come from the server, `DUCK_LSP_LOG`
shows them in the code action replies. To bring the link back, define the
server without the key:

```yaml
language-servers:
  gopls:
    command: gopls
    except-code-actions: []
```

A `check` validates a file the moment it is written, in the directory of
the file and through sudo for a save as root. When it exits with an error
the old file goes back on disk, the buffer keeps your text as modified,
its output shows in a popup and the places it names go to `]q` and
`space q`. `:w --no-check` writes without it. Only checks that look at
the saved file alone ship in the catalogue. A check of the whole system
configuration fits a project or a server, for example:

```yaml
languages:
  nginx:
    check: { command: nginx, args: [-t] }
  systemd:
    check: { command: systemd-analyze, args: [verify, "{file}"] }
```

Features for `only-features` and `except-features`: `format`,
`goto-declaration`, `goto-definition`, `goto-type-definition`,
`goto-reference`, `goto-implementation`, `signature-help`, `hover`,
`document-highlight`, `completion`, `code-action`, `document-links`,
`workspace-command`, `document-symbols`, `workspace-symbols`,
`diagnostics`, `rename-symbol`, `inlay-hints`, `linked-editing`,
`call-hierarchy`.

```yaml
languages:
  typescript:
    language-servers:
      - name: typescript-language-server
        except-features: [format]
      - name: biome
        only-features: [format, diagnostics]
```

## A new language

A language with a grammar the binary does not have needs it compiled. Give
the grammar source, then fetch and build it:

```yaml
languages:
  gleam:
    scope: source.gleam
    file-types: [gleam]
    roots: [gleam.toml]
    comment-token: //
    indent: { tab-width: 2, unit: "  " }
    # A server only this language uses can be defined inline.
    language-servers:
      - name: gleam
        command: gleam
        args: [lsp]
    grammar:
      git: https://github.com/gleam-lang/tree-sitter-gleam
      # The commit to build, pin one so builds repeat.
      rev: <commit>
```

```sh
dk grammar fetch gleam
dk grammar build gleam
dk grammar check gleam
```

This needs git and a C compiler. The grammar lands in
`~/.config/duck/runtime/grammars`, highlighting and other queries go into
`~/.config/duck/runtime/queries/<language>/` (`highlights.scm`,
`indents.scm`, `textobjects.scm`, `injections.scm`, `locals.scm`).
A grammar shared by several languages is defined once in a top level
`grammars` table and named in `grammar: { name: ... }`.
